El problema

Las ideas se pierden en el cambio de contexto.

Estoy trabajando en una cosa y aparece otra: un pendiente, una idea, algo que tengo que revisar después. Si no la escribo en ese segundo, se va.

El problema no es la falta de apps. Es que todas piden demasiado antes de dejarte escribir: abrir, elegir una carpeta, ponerle título, asignar una etiqueta. Para cuando terminas ese proceso, ya perdiste el hilo de lo que estabas haciendo — y a veces también la idea.

la hipótesis

¿Y si la app solo hiciera una cosa bien?

Partí de una restricción: si la captura no ocurre en menos de tres segundos, la app falló.

Eso descartó casi todo lo que una app de notas suele tener. Sin carpetas, sin etiquetas, sin títulos, sin editor de texto enriquecido.

Solo dos listas:

Hacer — lo que tengo que hacer
Pensar — lo que tengo que pensar o revisar

Esa separación resuelve el 90% de lo que capturo en el día. Un pendiente accionable y una idea sin resolver no son lo mismo, y mezclarlos es lo que hace que las listas se vuelvan ruido.

brand

De Catch a catchwisp

El nombre original era Catch. Directo, pero imposible de registrar y sin dominio disponible. Sumé "wisp" (algo tenue, que se desvanece) porque describe exactamente lo que la app intenta atrapar: la idea antes de que se vaya.

Wordmark: Probé varias tipografías antes de llegar a Baloo. Es geométrica sin ser fría, y en minúscula el conjunto se lee compacto, como una nota rápida y no como un logo corporativo.

EL PRODUCTO

Tres decisiones que definieron la interfaz

El campo de entrada siempre visible

No hay botón de "nueva nota". El input está fijo, siempre en foco al abrir. Abrir la app y escribir es la misma acción.

Las dos tabs, no un selector

Consideré un menú desplegable para elegir lista. Lo descarté: agregaba un paso a la acción crítica. Con dos tabs, cambiar de lista es un toque y el estado es visible sin abrir nada.

Estados vacíos que no venden nada

El estado vacío no tiene ilustración ni onboarding. Solo una línea que dice qué va ahí. Si la app promete velocidad, la primera pantalla no puede pedir que leas.

Sistema Visual & UI/UX

Un sistema chico, pero completo

Antes de diseñar pantallas armé la base. Es un producto de una persona, así que el sistema tenía que ser lo suficientemente pequeño para mantenerlo solo, y lo suficientemente estricto para que las decisiones no se repitieran cada vez.

DE DISEÑO A PRODUCCIÓN

Diseñado y enviado a producción por una persona

Los tokens del sistema de diseño se implementaron como configuración de Tailwind, así que el archivo de Figma y el código comparten la misma escala. No hay traducción manual entre diseño y desarrollo, y por lo tanto no hay deriva entre ambos.

El multiidioma se resolvió antes del primer commit de UI. Meterlo después habría significado tocar cada componente.

  • Vite + React + Tailwind
  • React Router para la navegación
  • i18n con soporte español e inglés desde el primer día
  • Persistencia local con localStorage
  • Deploy continuo en Vercel conectado a GitHub
